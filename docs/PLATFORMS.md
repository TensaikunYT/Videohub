# Platform support

Windows remains the established platform. Linux (including **Omarchy** — Arch Linux + Hyprland + Wayland + Walker + `uwsm` + `mise` + Btrfs) has been verified on a real Linux host for shell launchers (`setup.sh`, `open.sh`, `update.sh`, `uninstall.sh`), `mise`/stripped-GUI-`PATH` resolution, freedesktop `.desktop`/autostart generation, live hub APIs, MCP/CLI tools, FFmpeg chunked + partial rendering, sound/WAV fallback, `/proc` inventory, `taskset` CPU affinity + niceness, process-group Stop, archive verification, and `trash-cli` + freedesktop Trash; physical GPU encoding (VA-API/NVENC/QSV) and live graphical Wayland session checks (Walker, Chromium/Brave app window, `zenity`, `notify-send`/mako, Nautilus `FileManager1`) still benefit from testing on your desktop hardware. macOS remains covered by injected tests and awaits hardware verification.

`server/platform.js` owns operating-system integrations. The queue, cleanup, UI and MCP tools keep the same public contracts. Everything stays local: the hub listens on `127.0.0.1`.

## Windows security behavior

Windows lifecycle and runtime paths do not add execution-policy overrides. Setup/update/uninstall call the shared Node installer directly; PowerShell compatibility wrappers respect existing script policy. Runtime integrations do not compile inline C#, use custom P/Invoke or generate PowerShell scripts. Folder selection loads the installed WinForms dialog and has a typed-path fallback; reversible deletion uses an installed .NET API while retaining the Bin safety checks. Normal launch, shortcuts and login startup use the installed Node runtime directly. The old VBScript/PowerShell launchers are no longer shipped; update migrates owned shortcuts/startup entries and recycles those files only after safe reference checks. Unknown/unreadable entries or migration failures retain the old launcher files with a warning; migration does not execute retired helper binaries.

This reduces unnecessary launch/compiler machinery. It does not certify the source or a downloaded archive as malware-free, establish a false-positive verdict, provide a trusted publisher signature or guarantee SmartScreen, Smart App Control or antivirus acceptance. Execution-policy errors, reputation warnings and malware detections need their exact messages to be assessed. No security-tool exclusions, policy downgrades or automatic file submissions are part of VideoHub. Older distributed copies need an explicit update; local source changes do not alter them. See [Windows security guidance](WINDOWS-SECURITY.md).

## Omarchy (Arch Linux + Hyprland + Wayland)

Omarchy is an opinionated Arch Linux desktop built around Hyprland (Wayland), `uwsm`, Walker + Elephant, `mise`, PipeWire, `mako`, Nautilus (`glib2`/`gio`), Chromium (or Brave/Helium) and Btrfs. VideoHub handles each of these directly without distro-fragile lock-in:

- **Packages** — install Node 22+ via Omarchy's default `mise` (`mise use -g node@22`) or pacman (`sudo pacman -S --needed nodejs npm`), plus `sudo pacman -S --needed ffmpeg chromium` (skip `chromium` if you already use native `brave`, `helium-browser` or `google-chrome`). Optional graphical folder dialog: `sudo pacman -S --needed zenity`. Optional GPU video drivers: `libva-mesa-driver` (AMD VA-API), `intel-media-driver` and/or `vpl-gpu-rt` (Intel VA-API / QSV), `nvidia-utils` (NVIDIA NVENC).
- **GUI / Walker / `mise` PATH** — Hyprland/Walker/`uwsm` sessions do not always source interactive shell RC files. `setup.sh`, `open.sh`, `update.sh`, `uninstall.sh` and `server/platform.js` search `~/.local/share/mise/shims`, active `mise` Node installs, `~/.local/share/omarchy/bin`, `~/.local/bin`, `/usr/local/bin` and `/usr/bin` automatically, and `.desktop` files embed the resolved absolute Node binary path.
- **Walker launcher & no `~/Desktop`** — `./setup.sh` installs `~/.local/share/applications/videohub.desktop`, picked up immediately by Walker (`Super + Space`). When `~/Desktop` is absent or disabled (`xdg-user-dir DESKTOP` pointing at `$HOME`), VideoHub skips the Desktop copy instead of creating an empty `~/Desktop` directory. Optional Hyprland keybind: `bindd = SUPER SHIFT, V, VideoHub, exec, ~/Apps/VideoHub/open.sh`.
- **Wayland app window & headless rendering** — opening VideoHub passes `--ozone-platform-hint=auto --app=http://127.0.0.1:7788` to Chromium/Chrome/Brave/Helium/Edge under Wayland so the UI opens sharply without XWayland blur. Headless Puppeteer renders pass `--ozone-platform=headless` and `--disable-dev-shm-usage` so renders never flash a window on your Hyprland workspace or exhaust `/dev/shm` on multi-worker 1080p/4K jobs.
- **Autostart under `uwsm` / Hyprland** — enabling login startup writes `~/.config/autostart/videohub.desktop` (`open --server`, `NoDisplay=true` so it stays out of Walker's app list). If your Hyprland/`uwsm` setup disables XDG autostart, add `exec-once = /path/to/VideoHub/open.sh --server` to `~/.config/hypr/autostart.conf`, or skip autostart completely (agent `hub_*` calls start the server on demand and it idles out cleanly).
- **Notifications, files & audio** — render-complete notifications use `notify-send -a VideoHub -i <icon> --` (displayed by `mako`); revealing a file invokes `org.freedesktop.FileManager1.ShowItems` (highlights the file in Nautilus) and falls back to `xdg-open` / `gio open`; browser audio preview works directly through PipeWire.
- **Btrfs Trash & outputs hard links** — VideoHub delegates Trash to `gio trash` (`glib2`, preinstalled with Nautilus) or `trash-put` first, falling back to spec-compliant freedesktop Trash (`~/.local/share/Trash` or `<mount>/.Trash-<uid>`). If a workspace sits on a separate unmounted Btrfs subvolume and neither `gio` nor `trash-put` can trash it, VideoHub leaves the file untouched and reports why rather than permanently deleting it. Daily links in `<workspace>/outputs/` use hard links on the same subvolume and fall back automatically to safe copies across subvolumes.
- **RAM hog monitor** — hides Hyprland, Waybar, Walker, Elephant, `mako`, SwayOSD, `uwsm`, `xdg-desktop-portal*`, PipeWire/WirePlumber, SDDM and Btrfs/kernel threads so the Renders page only lists real user apps (browsers, editors, Blender, OBS, VMs).

## Optional Linux tools

Native Chromium, Chrome, Brave, Helium or Edge and `ffmpeg` are needed for renders (`ffprobe` enables stream metadata; sound mixing of `.wav` files also works in pure JS if `ffmpeg` is temporarily absent). Setup prints package-manager hints (`pacman`, `apt`, `dnf`) and does not silently install system packages. Install `zenity` (or `qarma`, `yad`, `kdialog`) for a graphical folder picker, `taskset` (`util-linux`) for CPU-core affinity, `notify-send` (`libnotify`) for desktop notifications, and `pciutils` (`lspci`) for full PCI GPU model names (without `lspci`, VideoHub falls back to `/proc/driver/nvidia` and `/sys/class/drm`). Their absence does not disable the hub.

Trash helpers (`gio` from `glib2`, `trash-put` from `trash-cli`) are optional. The Node fallback writes restorable `.trashinfo` metadata and moves files rather than hard-deleting them. Home-filesystem paths use `$XDG_DATA_HOME/Trash` (`~/.local/share/Trash`); other mounted filesystems use a private `.Trash-<uid>` directory. If no safe Trash operation works, the source stays in place and VideoHub reports the refusal.

## macOS permissions and limits

The optional Desktop `VideoHub.command` launcher opens Terminal briefly. No unsigned `.app` bundle is created. After a blocked first launch, use System Settings → Privacy & Security → Open Anyway, then open the launcher again; `bash open.sh` from the installation is an alternative.

Finder may request Automation permission when VideoHub first sends files to Trash. If permission is denied or Finder reports an error, VideoHub keeps the source and reports the refusal. It does not fall back to permanent deletion. macOS has no supported CPU-core affinity API, so the Renders page hides core-power controls while retaining niceness, background QoS and RAM protection.

On Linux and macOS, raising priority after a slow period can require privileges. Restoration is best effort without elevation; an existing render may keep its lower nice priority until completion. A new render starts with its configured priority. The UI does not promise a precise CPU percentage when affinity is unavailable.

## Agent integration

Setup can target Antigravity CLI (agy), Claude Code, OpenCode or any combination. The agy MCP configuration and GEMINI.md are shared with other Google tools; setup only manages the VideoHub entry and marked rule. Skills share one source file and rules are limited to VideoHub's marked block. Existing unrelated settings and rules remain in their respective agent files. An OpenCode `AGENTS.md` causes OpenCode to prefer that rules file over Claude's global rules; setup prints this consequence and does not copy unrelated rules between agents.

## Not supported

- Snap and Flatpak browser wrappers are not used for Puppeteer renders; install a native browser executable.
- Linux CPU affinity without `taskset`, and CPU affinity on macOS; priority and RAM protection still work.
- Guaranteed restoration of Unix niceness without the required privileges; no elevated helper is installed.
- Permanent deletion as a fallback for an unavailable Trash or Recycle Bin.
- Native modules, compiled helper programs and unsigned `.app` bundles.
- Renders made from an older template are not rewritten. Their own browser lookup may need updating or the script may need to honor `VIDEOHUB_BROWSER`.
